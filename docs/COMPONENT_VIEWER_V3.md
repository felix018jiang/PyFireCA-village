# 燃料部位回放与网页重算（2026-10-05）

## 已实现的输入路径

普通照片/RGB分类只负责材质类别。案例沿用材质库的默认初始水分，用户不逐格填水分；模型仍保存活/死水分池和有效受热层的动态蒸发。部位拆分后的初始含水率按对应活/死质量计算。示例树格整格63.75%，树下细死燃料15.00%，上部69.47%；这些是合成参数库的假设，不是从照片测出的水分。

`run-components-v3 --viewer` 在原物理地图上回放各部位独立状态，可切换实际存在的部位ID。卡片显示原始节点的初始含水率、剩余可热解燃料、有效受热层剩余水、有效未燃表面温度、末次计算步平均HRR及已经发生的引燃时间。HRR不是两个采样帧之间的平均值；没有给燃烧部位填造火焰温度。

## 显示和数据契约

- `village-component-viewer-1` 与普通单状态V3回放分开识别。
- 地图、材质/地类/建筑索引、覆盖率和DEM按原物理格排列；动态二进制与引燃/燃尽/原因按独立节点排列。`component_cells.bin`和`component_ids.json`给出映射；清单明确`frame_then_component_node`。
- `component_burnable.bin`保留可燃掩膜。被排除格可以保留原材质质量，但不参与燃料/水分/HRR/温度/引燃指标；其unknown状态仍显示。
- 总览剩余燃料是所选部位剩余质量之和除以其初始可热解质量之和；初始含水率按所选干质量加权。温度取有效未燃部位最大值；水分和HRR取所选部位之和。
- 状态优先显示正在燃烧的部位；有部位燃尽、还有未燃或受热部位时为显示状态5“部分燃尽”；其余为有部位受热、全部所选部位燃尽、未燃/不燃/未知。状态5只用于显示，未修改求解器状态机。
- 地图没有所选部位时显示“此格无所选部位”，不把透明区域当成计算域外或燃料耗尽。卡片保留该格全部可燃部位，其他部位降低显示强调。
- 引燃计数/时间/原因按当前帧截止，避免把未来点燃信息放进早期回放。建筑轮廓和统计按所选部位汇总；没有建筑多边形来源时明确使用“建筑标注索引”，不伪造真实建筑ID。
- 下部着火/燃尽不等于整格或整栋建筑毁坏。部位配方、HRR和传输仍需独立物理标定。

导出在创建viewer目录前检查节点形状、初始燃料一致性和有序且覆盖0至结束时刻的快照。前端检查静态/动态长度、索引、唯一部位身份、时间、质量和可燃节点水分。`all`、`toString`等合法自定义ID不会与总览或标签字典冲突。

## 资源边界与重算

第一版部位网页会保留求解器采样快照，并在浏览器合并分块；分块导出不代表浏览器流式读取。默认回放估算上限256 MiB，预算包含原始节点数据与物理格聚合，超限在求解前拒绝。CLI没有采样间隔时明确使用60 s并记录；网页重算根据时长选间隔，最多101帧。

```bash
.venv/bin/pyfireca village run-components-v3 CASE_DIR \
  --components-config examples/village/vegetation_v3/components.synthetic.yml \
  --flame-contact-config examples/village/vegetation_v3/flame-contact.synthetic.yml \
  --internal-radiation-config examples/village/vegetation_v3/internal-radiation.synthetic.yml \
  --viewer --output runs/component-replay-new

.venv/bin/pyfireca village simulate-components-v3 runs/component-replay-new \
  --output-root runs/component-selected-new --port 8813 --no-browser
```

有完整有限图、受体面或独立燃烧曲线时，在首次运行中传对应配置；服务器从该结果的`*.resolved.yml`恢复。配置必须与运行清单一致，缺文件/不一致报错，防止静默切换模型。新作业只改起火点、时长及记录的采样间隔，重新执行几何、节点/边数和回放内存门禁。默认20,000节点、500,000辐射边、256 MiB回放预算；积分本身继续受保存配置的工作/收敛上限控制。

起火点按原物理格可燃掩膜判断，与当前显示部位无关。服务器`/api/config`声明模型与组件起火能力，只有与页面模型匹配时才显示重算控件。单状态服务不能让部位页面提交单状态模拟。源案例的中文标签、裁剪元数据、影像仿射和建筑分组保留；自包含回放复制原建筑ID映射。新结果的base-case现在也保存标签与元数据，源码快照包含网页资源。

## 验证记录

32项部位导出/纯JS回归加7项组件交互测试，覆盖状态/质量加权、未来信息屏蔽、排除节点、配置恢复与丢失拒绝、实际HTTP提交、完整有限图/受体方向保留及资源门禁。开发期间曾发现HRR标签、排除格水分校验、部位ID命名冲突和窄屏canvas超出stage的问题，均已修正；具体全仓库最终检查见PROJECT_PLAN 28.12。

浏览器实际验证高友村17×17、2 m裁剪，地形与RGB推测标签沿用原数据。切换树木上部后选择中心灌木格(8,8)并运行60 s成功，新结果仍是部位模型，显示初始水分49.40%、61帧；桌面1280×900与手机390×844均可查询部位，测试后恢复原窗口。截图与结果在`runs/component-interactive-browser-20261005/`。本组高友村沿用原跨格图加同格有限辐射，不把它称为完整有限图的大域性能验证。

回放和重算改善可审计性，没有补充动态火焰、风、飞火、结构坍塌或现场校准证据。接下来按PROJECT_PLAN优先完成源几何/风的适用域与独立验证设计，再进入校准和灾前防火线实验。
