# 影像识别材质后的默认含水率：简化输入，保留水分物理作用

更新：2026-10-04。用户希望用航拍/普通照片/卫星影像识别材质，不要求逐原胞输入含水率。本阶段明确采用**材质库自动提供固定初始含水状态，用户无需填写水分数值**的默认工作方式。现有V3已具备这一机制，本轮没有另加必须填写的水分配置，也未修改材质数值或热求解内核。

**后续开发已落实运行入口，见第7节。**第1–6节保留最初政策/审计阶段的记录，其中“本轮没有改网页”“M02仍要求文件”描述的是该历史阶段，不再代表当前入口。

## 1. 回答研究及产品问题

可以给每种已识别材质配一套确定的默认含水参数。它是“缺少现场水分数据时的基准情景”，不是“这一材质永远具有某个含水率”的物理常数。普通RGB图像可辅助识别枯黄/绿色、燃料类型等状态，但不能把图像颜色直接当作准确含水率测量值；影像材质分类本身也需记录错误和不确定性。建筑外观更不能直接揭示屋面下面的木构件、室内可燃物、涂层与构造。

[NWCG《Weather and Fuel Moisture》](https://www.nwcg.gov/publications/pms425-1/11-weather-and-fuel-moisture)说明含水率受季节及即时天气变化影响，活燃料与死燃料响应机制不同；死燃料的平衡水分主要受相对湿度和温度影响。它支持“初始水分属于情景变量，而非永恒材质常数”，并不支持本项目某个具体默认数值。

[斯坦福研究组的LFMC数据及关联研究](https://koningslab.stanford.edu/datasets)采用卫星数据估计区域活燃料水分；[USFS的2026遥感研究报告](https://research.fs.usda.gov/firelab/products/multimedia/webinars/predicting-what-burns-machine-learning-and-satellite-remote)使用实测训练、多源遥感、天气时间窗及植物种类等信息。这些是有数据和校验条件的估计，不等于肉眼从一张普通照片读出百分比，也不能将大尺度像元直接视为2 m原胞的实测水分。**现阶段不需要为了使用模拟程序先实现遥感含水率反演。**

## 2. 当前库其实已经使用固定值

`vegetation_materials.py`的每种profile保存固定活/死初始含水率；`physics_v3.resolve_vegetation_physics`按识别到的profile计算水量。用户不需要提供每格水分栅格。以下是现有`profiles.synthetic.yml`中实际值的汇总，**全部是合成基准假设，不是当地测量或本轮从文献拟合的推荐值**。

|V3地类/等效材质|总体默认干基含水率|内部活燃料默认|内部死燃料默认|
|---|---:|---:|---:|
|草地|30%|60%|10%|
|灌木|49.4%|80%|12%|
|林下枯落物|17.25%|60%|15%|
|树木等效燃料|63.75%|90%|15%|
|建筑等效可燃燃料|10%|不适用，无活燃料|10%|
|裸地/道路|不适用|不适用|不适用|

总体数值使用现有库的干质量比例加权：草地活/死0.4/0.6，灌木0.55/0.45，枯落物0.05/0.95，树木0.65/0.35，建筑0/1。改变活死比例时总体默认值随之改变，不应将上表总值又独立固定而同时声称保留原水量。林下类中的少量活燃料和所有比例同样是模型假设。

**前台只需要“材质类别→默认参数库”，不要求选择活水分/死水分。**内部保留两个预设值，是为了让已经实现的树下死燃料和树冠等部位分配正确，不增加用户填表任务。若确实只有单一可燃材料（例如明确的干木材），可以使用一个默认值；上面的建筑10%代表已声明的等效可燃燃料，不能解释成砖、瓦、混凝土均会燃烧且含水10%。

另一个较早的M02调查工作流已有`material_cards/moisture.initial.synthetic.yml`：木材/竹材/茅草0.10，草地/枯落物0.25，灌木0.60，树木等效0.60，均标为情景假设。**这是另一套单状态案例基准，不能与当前V3活死库混用。**M02命令仍要求显式指定该文件，本轮未修改其evidence-only要求或制造实际已填写的现场调查值；本政策的默认自动分配首先适用于正在运行的V3影像→profile→原胞工作流。

## 3. 为什么不把树木整体平均值套给所有部位

同一种“树木”原胞可能同时含有干落叶、死枝和活体叶片。现有总体63.75%不表示每个部位都是63.75%。当前分层假设下，树下死燃料为15%，上部混合燃料约69.47%；两者由各自活/死干质量和水分预设自动求得。

本轮用固定合成`草地→树木→树木`链及同一高友村289格裁剪，比较三种方法：

1. 现有固定材质库，保留活/死水分。
2. 每物理原胞的总体含水率保持不变，但将它均匀赋给活/死燃料；**每格总水量以及分层后总有效受热水量保持不变**。
3. 全部水设为0，作为机制/数值压力对照，不作为默认预设。

燃料、受热质量、引燃阈值、HRR曲线、接触及同格辐射配置保持；dt=0.5/0.25 s，合成截止1200 s、裁剪600 s。

|dt=0.25 s结果|现有自动默认|活/死均匀同一值|零水分对照|
|---|---:|---:|---:|
|合成链树下引燃部位数|2|0|2|
|合成链首个树下引燃（s）|54.0|未引燃|36.5|
|合成链第二个树下引燃（s）|178.83|未引燃|146.08|
|高友村树下引燃部位数|12|9|27|
|高友村建筑基部引燃原胞数|5|5|18|

合成链原/均匀两法的总水都是41.52 kg，总有效受热水都是10.56 kg；均匀法只是把树下15%提高到63.75%，同时降低上部水分。**可见空间/部位分配会改变传播，即使水量守恒。**这不是证明15%是当地正确值，而是证明“不加用户输入”与“删掉活死区别”并非同一件事。

现有默认和均匀法的两步长引燃掩膜一致，最大引燃时间差分别0.75 s、1.25 s。零水分裁剪在0.5/0.25 s间有一个高处建筑原胞的差异（14/15），故主比较的全部步长验收**未通过**；报告保留失败，不能把该零水分结果当作稳定的现实预测。追加复核在0.25/0.125 s间又有一个高处树木部位差异（21/22）；0.125/0.0625 s两步掩膜相同，最大引燃时间差0.25 s。细步长结果仅为开发期局部数值跟进，不能把单次相邻细化一致当作完整零水模型验证；不改变原验收失败记录。主12次加2次复核共14次求解，源预算误差最大约1.13×10⁻⁴ J，低于预先保存的10⁻³ J标准。水分对照是指定参数条件下的敏感性证据，不是现实火灾校准。

## 4. 后台计算保留什么

含水率M为干基比值：

\[
M=\frac{m_{\rm water}}{m_{\rm dry}},\quad
m_{w,0}=m_{\rm live}M_{\rm live}+m_{\rm dead}M_{\rm dead}.
\]

0.10表示干质量的10%，不是湿重的10%；100%甚至更大的干基含水率对活燃料不应被误当作非法百分比。前台可显示百分数，后台统一kg/kg_dry。不同燃料量原胞的含水质量kg自然不同，应固定的是含水率，不是每格固定同一个水质量。

原胞引燃前只计算有效受热层的水：`m_water_effective = m_dry_effective × M`，不要求先蒸干整棵树/整栋建筑的全部水。采用现有的升温—蒸发—干燃料升温的分段能量计算，蒸发耗能约`m_water_effective × L_v`。水状态随受热减少；**固定初始含水率不等于每个时间步恢复固定含水率**，否则水会被无限补回，反而无法正常升温引燃。

这是向量化、已实现的简化热模型，不是每步重新反演水分、植物生理或复杂水文模型。没有必要为了减少前台输入改成含水率经验概率因子、再丢掉能量账目。现内核并非完整活体燃烧模型：未燃受体的有效层蒸发与燃烧后HRR对水分的反馈要区分，当前指定燃烧曲线尚无这种反馈。该限制不会因默认含水率而消失。

## 5. 项目执行方式与研究边界

第一版输入流程确定为：**影像识别/人工确认材质 → 自动选择固定材质profile → 分配燃料、水分及热参数 → 模拟**。无水分观测时使用现有合成基准，并在输出/论文方法中声明。普通用户不逐格填写含水量；有实测信息时在高级参数中覆盖并记录来源。默认值的应用是输入假设，不得在输出中改标为影像实测或现场测量。

后续可增加全场景的“偏干/基准/偏湿”选项或天气驱动估计，但不作为第一版运行的必填项。研究防火线时，至少用数个明示水分情景复核布局排序：只在一个固定水分下得到的最优方案，应限定为该情景下最优，避免把默认值造成的排序当作普遍结果。简化输入不等于必须忽略水分不确定性。

可见的绿色/枯黄状态更适合先影响燃料类型或活死比例，再结合全局天气情景；在无训练/实测数据时，不直接从颜色映射精确M。真正的光学/微波含水率估计应作为未来有标定数据的扩展，不能与当前RGB材质假设混为一谈。
