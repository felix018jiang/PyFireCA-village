# 村内建筑防火线的精确搜索与最优性认证

日期：2026-10-24。承接[替代位置对照](HERITAGE_POSITION_CONTROLS_20261024.md)。本轮将人工方案比较推进为自动组合搜索：先验证小实例的最优性，再核算331栋扩展成本。材料、25 m²点火、1200 s、无风、1 m/0.5 m屋面尺度与0.5 m辐射求积沿用现有设置。

## 问题与算法

对候选建筑集合C选择拆除子集D。目标按词典序最小化`(拆除标注数量, 名义屋面面积之和)`，约束为每个设计点火情景和每个尺度下，鼓楼与风雨桥均未引燃。实际清空面积与共享屋面保留面积继续记录，不将它们混入本轮已明确的加性名义面积目标。现实退让、住户成本不在这次搜索变量中。

算法是按数量分层的精确组合搜索。首先实际验证初始可行解，随后依次搜索0、1、2……栋。每层通过最佳优先的前缀队列按名义面积非递减生成组合；前缀的界限是已选面积加上完成该数量所需的最便宜剩余建筑面积，因此不必预先构造整层组合表。现有可行解只能排除数量更大或同数量面积更大的组合，不用于推断火势单调性。

每个组合按冻结顺序调用CA。任一有效核心引燃即可作为否决反例并停止该组合的后续模拟；通过必须完成全部情景和两个尺度。错误、缺失和源层被全部拆空都不能成为保护成功。更优位置上的未知结果会阻止最优性认证，但可以继续报告已验证可行方案。

最优性依据是完整覆盖：设算法返回k栋、面积a的通过方案，则所有少于k栋的组合，以及k栋内面积小于a的组合，都必须已有有效失败反例。面积并列者允许返回其中一个；算法不宣称最优解唯一。若预算耗尽，返回当前可行解、未知项和`incomplete`，不返回全局最优。

## 实现边界

- `planning/building_search.py`：与CA无关的组合生成、词典序搜索、初始解核验、情景缓存、预算和认证状态。
- `planning/engines/roof_search.py`：复用现有独立屋面CA、整栋拆除、源优先序和双核心评价；每个点火情景先固定候选/可能替代源/核心的共同细化布局，再比较全部方案。
- `scripts/run_heritage_exact_search.py`：冻结输入与源码、保存逐次原生评价和缓存、运行或恢复小集合搜索。
- `scripts/audit_heritage_exact_search.py`：独立枚举全部小集合子集，核对CA反例/完整通过、面积、源预算、能量与一次原生末态恢复。
- `scripts/assess_heritage_exact_search_cost.py`：组合数、面积上界内组合数、实测耗时与全候选网格资源下界；不启动全村搜索。

缓存绑定完整问题身份、建筑集合与情景。冻结源码快照与完整生产评价保留在运行目录。历史确认数据没有直接当作新布局下的缓存，初始三栋在本轮共同布局上重新验证。

## 三类验证

1. 手算与随机表：组合互补、同数量更小面积、零拆除最优、无解、非单调响应、未知项、预算恢复和输入改变。30个七候选非单调随机表与独立完整穷举对比。
2. 双尺度物理控制：沿用已有合成木建筑材料；25 m²源建筑、传播中间建筑、两个核心和无关候选。独立评价四个子集的两个尺度，核对搜索找到只拆中间建筑的解。
3. 岜团村小集合：候选为B0061、B0071、B0076，共8个子集。使用此前保存的B0075、B0071与B0062不利点火区，每个情景运行1 m/0.5 m，初始三栋重新核验。B0071拆除后的替代源按旧优先序确定。这是设计集和小集合最优性验证，已有情景再次进入搜索后不充当新的独立留出。

## 扩展331栋的核算口径

零至两栋共有54,947个组合；三栋共有5,989,445个组合。若原三栋在扩展后的统一问题中继续有效，就可把更大数量层排除，再比较更小面积的三栋组合；新布局上的三栋上界必须重新核验。

全村成本包含CA次数和共同离散资源。当前适配器会细化所有候选、可能替代源与核心。对原始109,856个节点，按每个细分多边形面积不超过尺度平方计算，全部屋面1 m节点数至少183,344，0.5 m至少414,344；后者已经超过现行200,000上限。该结论只需几何下界，不构造大辐射图，也不提高资源上限。

耗时核算将分别列出“每组合一次快速失败”与“每组合完整六次评价”的串行敏感性计算，使用本轮实测而非承诺运行时间。全村统一细化图更大，不能把小实例耗时当成全村预测，也不能把理想并行加速直接当实际耗时。

## 小集合最优性结果

岜团村8个子集全部取得有效判定，原三栋通过三个情景的两个尺度，其他7个子集各有CA失效反例。结果为`optimal`，名义面积451.240456 m²；这是声明的三候选、三设计情景内的最优性证书。

| 拆除集合 | 判定 | 有效否决或通过依据 |
|---|---|---|
| 无拆除 | 失败 | B0075源，1 m下鼓楼889 s引燃 |
| B0061 | 失败 | B0075源，1 m下鼓楼889 s引燃 |
| B0071 | 失败 | B0075源，1 m下鼓楼889 s引燃 |
| B0076 | 失败 | B0071源，1 m下鼓楼1098 s引燃 |
| B0061＋B0071 | 失败 | B0075源，1 m下鼓楼889 s引燃 |
| B0061＋B0076 | 失败 | B0071源，1 m下鼓楼1098 s引燃 |
| B0071＋B0076 | 失败 | B0062源，1 m下风雨桥988.36 s引燃 |
| **B0061＋B0071＋B0076** | **通过** | 三个情景、两个尺度均保护两个核心；B0071拆除后按冻结优先序由B0067起火 |

失败只需有效反例，未计算的后续情景不标成成功。实际21次CA中，1 m为14次、0.5 m为7次；若对8个子集一律完成六次则为48次。失败早停和初始解复用减少了27次评价，即56.25%。这一比例属于本小实例，不作为全村固定加速比。

源码冻结、能量、核心身份、25 m²源区与同源跨尺度预算均通过审计。保存的一份三栋原生案例恢复后全部末态数组一致。完整入口恢复21条缓存、0次新增CA，结果不变。新搜索器及相邻模块合计127项测试通过，包括非单调真值表、同栋数面积比较、未知状态阻止认证、数量证书与面积证书区分、入口恢复和输入变化拒绝。

结果与证书见[完整机器报告](results/heritage-exact-small-20261024.json)。首轮21次求解和随后0求解恢复的记录分别保留在运行目录的`search-result-first-execution.json`与`search-result.json`中。

## 331栋成本结论

全村331栋中，名义面积小于原方案的三栋组合有1,250,271个；与零至两栋合计1,305,218个潜在更优组合。这里使用当前方案作为成本参照，尚未在新的全候选共同细化布局上验证其可行上界。

本轮单次评价实测中位耗时为1 m约27.67 s、0.5 m约98.95 s。按这些小实例耗时作串行敏感性换算：

| 覆盖范围 | 假设每组合一次最快1 m否决 | 假设每组合完整三个情景、两个尺度 |
|---|---:|---:|
| 零至两栋的54,947个组合 | 14.97天 | 241.57天 |
| 加上更小面积三栋，共1,305,218个组合 | 355.63天 | 5,738.18天 |

两列是假设情景下的算力换算，不是严格耗时上下界或完工预测。全村共同细化图更大；资源上限和源层全部拆空的处理也需在全村问题中明确。当前适配器将空源层返回未知，绝不把没有发生火灾计为保护成功。计算明细见[成本报告](results/heritage-exact-cost-20261024.json)。

本轮结论是：精确搜索器已能自动找到并认证小问题的最优解；直接扩展331栋需先处理共同细化资源、验证初始可行上界，并提高有证明依据的排除效率。下一步应针对这些计算瓶颈做有预算的扩展试验。全村搜索和村外试验均未启动。

## 可复现入口

新运行使用配置`examples/research/heritage/batuan-exact-small-20261024.json`，运行`scripts/run_heritage_exact_search.py --config <配置> --output <新目录>`。同一生产版本下加`--resume`即可恢复；输入或代码改变时明确拒绝混用缓存。

已完成实验的生产版本与后续工作区版本独立保存，使用生产快照可恢复本轮结果：

```sh
task_run="$PWD/runs/research/heritage-exact-small-20261024"
PYTHONPATH="$task_run/source-snapshot/src" .venv/bin/python \
  "$task_run/source-snapshot/scripts/run_heritage_exact_search.py" \
  --config "$PWD/examples/research/heritage/batuan-exact-small-20261024.json" \
  --output "$task_run" --resume
```
