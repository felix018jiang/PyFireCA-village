## 1. 当前代码判断

当前已有热传播求解器、矢量建筑资料、情景评价外壳、研究缓存与多情景搜索经验。独立屋面建筑干预及固定核心评价已完成接口和技术验证；当前优先缺口是源范围、可拆资格、重叠建筑语义及物理适用性核查，后续才是离散建筑搜索，不需要重写整个 CA。

本轮新增模块：`planning/roof_thermal.py` 划分屋面和构建物理传热图，`planning/engines/roof_heritage.py` 接通核心/单方案评价，`scripts/run_heritage_roof_study.py` 冻结并运行显式情景，`scripts/audit_heritage_roof_runs.py` 使用保存的拓扑复现完整末态。复用 V3 热时钟、蒸发/燃料/能量核算及有界接触算子；旧单状态入口继续保留为回归对照，不能混用两种状态表示的结果。

现有植被清理管线明确保留建筑；现有总民居/桥评分不能直接替代“指定鼓楼与风雨桥必须保护”。已有的村内外清理通过结果，也不构成村内建筑起火后的核心保护结果。

本计划的“复用”分三种：直接调用已存在接口；经明确扩展后调用；只借鉴组织方式。第三种不能当作已有可运行模块。

## 4. 阶段与依赖

```text
P0 输入与协议冻结
 → P1 单方案真实拆除＋固定核心评价
 → P2 小规模最小拆除闭环（第一个交付里程碑）
 → P3 有界扩展精确搜索与可靠排除界限
 → P4 可实施退让与连续廊道
 → P5 广泛情景、物理与跨村落研究验证
```

P5 所列基础检查并非全部推迟：身份、共享格、边界和能量一致性从 P0/P1 就执行，首个闭环也要有完整确认。后期扩大检查的范围和证据等级。

### P0：冻结对象身份、候选范围和最小实验协议

**交付：**核心清单、普通建筑目录、禁改清单、点火规则、设计/留出配置和输入审计摘要。

- 核定真实鼓楼与风雨桥 ID。区分建筑、屋面、附属物和重复/嵌套标注，不能把现有标注总数直接当住户数或可独立拆除栋数。
- 从普通建筑中指定不可拆的固定源，冻结其点火位置/方式；核心本体内部起火单列，不混入首轮传入保护任务。
- 定义候选目录及来源。首轮小集合是技术验证范围，不能仅选易取得好结果的建筑；保留扩大候选域的安排。
- 检查核心和关键近邻的共享温度格、矢量间距、地表来源。不能在共享格把两个对象同步点燃的问题未解决时声称建筑级真实保护。
- 明确拆除后露出地表、残余木构件是否清除。原 RGB 屋面类别不能作为拆后地表证据；未知地表需调查或显式假设及敏感性。
- 冻结首轮目标为设计情景中核心零引燃、数量优先面积次之；设 CA 调用预算及无效评价处理规则。

**验收：**每个核心都能定位到明确几何和模型对象；候选与禁改集合不冲突；源和观测可追溯；缺失项有状态而非默认零值。若鼓楼资料未齐，先给合成双核心案例与真实桥梁单目标测试，不标为真实双目标研究已完成。

### P1：打通单个建筑拆除方案的物理评价

**交付：**对任意手工指定的合法拆除集合，返回逐核心对象引燃、普通建筑结果、拆除代价及诊断。尚不进行大规模搜索。

建筑干预必须按以下顺序完成：

1. 验证行动资格，复制基准输入，在矢量建筑清单中应用行动；基准案例保持不变。
2. 从行动后的轮廓重算覆盖与归属，保留未拆建筑几何。删除主归属元胞会误删同格其他建筑，因此禁止仅按原 `building_index == i` 擦除整格。
3. 重建覆盖率、面积、燃料/水分质量、热容、HRR/可用能量、源/受体高度、燃烧与引燃掩膜、材质和地表证据。新露出地表按预定行动条件处理。
4. 重建当前物理配置支持的辐射连接；接触算子使用新的几何与参数。未来如有遮挡模型，拆后遮挡也须更新。
5. 绑定环境和固定点火源，重建对象观察。被拆对象不再作为活跃热对象，但保留在干预账本中；核心集合始终相同。
6. 运行 CA，使用当前请求的建筑几何统计结果，记录每个核心 ID 的首次引燃、同一保留普通建筑群体的损失和完整性诊断。

**验证重点：**零拆除与基准逐项一致；拆除只改变声明行动及其物理后果；邻近保留建筑未被误删；禁拆目标被拒绝；输入不被修改；能量/面积一致；源仍实际点燃；源点燃不触发核心失败；核心任一部分引燃必须触发失败。

使用至少一组“删除中间连接可改善”的机制案例和一组“隔空辐射仍可跨越”的案例，验证模型没有把空地自动视为绝热墙。双源受热、双核心保护和共享格处理也要覆盖。已有桥梁细网格案例可提供机制参考，不能代替新的拆除验证。

**阶段门槛：**手工方案完整运行后，物理图、对象映射、观测和代价一致；没有这些证据不进入优化阶段。

### P2：小规模最小整栋拆除闭环

**交付：**一个统一入口，完成基准、枚举、入选方案冻结、独立确认以及地图/清单导出。这是最高优先级里程碑。

- 在冻结的有限候选集合中按 \(K=0,1,2,\ldots\) 枚举，按面积比较同数量方案。记录总候选数、已查数、合法排除项与未知项。
- 对零引燃目标，可以在有效核心失败时停止筛查。通过必须覆盖全部设计情景并完成时长；入选与主要对照保存完整模拟。
- 设置无干预、几何近邻优先、目标导向贪心作为基础对照。保留全部同等或接近的可行备选，供住户与文化空间条件进一步筛选。
- 输出是否已证明有限候选集最小值；预算耗尽、求解失败或未知方案阻断证明时，输出当前最好值及覆盖范围。
- 首版采用固定源，论文结果明确条件范围。固定源方案只是在该源条件下最小，不能直接决定全村哪些房屋应拆。
- 同一保留普通建筑集合与基准配对，分开列主动拆除损失和火灾引燃。对可能增加的普通建筑风险及社区条件明确标注。
- 预先冻结确认规则；留出结果不得反向参与本轮搜索。确认未通过时仍保留原选定方案和失败记录。

**验收：**合成双核心案例能给出可手算核对的最少栋数；组合才有效的案例不能被贪心漏解而当作无解；零拆除已通过时返回零拆除；无解/未知/通过状态明确；同一输入恢复运行不额外计算已有兼容物理结果。

**可交付的研究结果：**指定源条件下，哪些建筑被选择、为什么、核心是否通过、拆几栋/多少面积，以及结果在独立确认中的表现。真实鼓楼数据齐备后才形成真实村落的鼓楼＋桥联合结果。

### P3：有预算的分支定界扩展

**交付：**候选资格与细化范围分开冻结的共同布局、有证明依据的排除规则，以及更大候选集的预算—覆盖结果。保留P2小实例精确证书。

- 保留原三栋作初始可行解，在新共同布局实际核验后才形成数量与面积上界。
- 最多拆K栋时，只需预建源优先序前K＋1项可能起火区；细化种子、核心、可能源及完整背景在搜索前固定，计划之间不变。
- 按数量和名义面积搜索，使用数量界、面积前缀下界及严格热输入不变支配；没有证明的图距离或传播路径不能永久排除合法建筑。
- 已知失败反例优先检查仅改变顺序。任一有效核心失效即可拒绝，通过必须全部情景与双尺度完成，未知不能被当成成功。
- 同时冻结CA总次数、软时限和资源上限；报告逐层覆盖、合法排除项、尚未判定的更优组合及数量上下界。跨恢复的CA总预算不得自动重置。
- 复用现有搜索器、独立屋面适配器、原生保存和冻结缓存；村落配置与审计留在研究脚本，不重构无关模块。

**验收：**有/无剪枝的已知最优实例目标一致；容量与源覆盖通过；初始解完整核验；预算停止明确标为未完成。只有所有更优方案被有效反例或可靠界限排除时才认证最优。重复与恢复结果一致；任一核心不可被牺牲；新增候选或布局不会混用旧缓存。当前8候选试验的具体预算见[扩展里程碑](HERITAGE_EXACT_EXPANSION_20261024.md)。

早期DPV、图引导与局部交换可作为未来情景调度或可行上界生成手段；本轮不实现，也不以它们代替最优性证明。

### P4：建筑退让、文化活动空间与廊道可实施性

**交付：**整栋拆除与有限退让行动的统一比较，实际廊道几何，以及对应住户/使用空间影响。

- 将二元变量扩展为每栋一个有限行动目录；保留面积、可使用性、结构可拆分性和搬迁影响由核定数据给出。
- 对选定路线与净宽做建筑/檐口冲突、连续性、桥头通行和鼓楼活动场地检查；同一建筑与住户去重计量。
- 搜索增加拆除替换为退让、行动等级交换和路线替换；优先沿已有巷道与空地，是否采用由完整复算决定。
- 按拆除上限扫描最小损失面积，保留数量—面积—住户影响档案。若总体迁移被允许，新址火灾影响同时进入模型。

**验收：**没有几何上不可用的残屋；廊道不能穿过保留檐口；桥体与两端功能均有检查；公共空间约束不是装饰性展示；退让确实改变物理输入，且与整栋方案公平比较。

### P5：全源情景、物理可靠性与跨村落研究

**交付：**支持论文主结论的环境适用范围、数据依据和跨村落配置规律。

- 从固定源扩展为保留建筑条件下的全源加权评价，固定总起火机会并显式重分配权重；另做同源配对机制对照。若采用概率解释，先核定抽样分布与不确定性估计方法。
- 扩大风、材料、含水率、燃烧强度和时长检查；查清目前静态辐射倾斜的适用范围。
- 检验飞火和必要的遮挡/有限面源机制，先验证建筑干预适配与观测兼容，再进入研究比较。不能仅打开配置开关即视为已验证。
- 检查关键局部细网格与时间步；局部域使用完整周围热源或有依据的时变边界。继承粗 DEM/RGB 地表的细网格不等于新增实测精度。
- 对独立村落冻结协议进行外部评价，分析密度、间距、核心位置、风向和候选资格如何影响最小干预，不预设统一安全宽度。
- 补充居民/文化活动调查、可实施性和分配影响，形成能支持遗产与社区共存的结果。

## 5. 结果与缓存契约

**物理结果缓存**绑定完整行动后请求、环境、点火、求解器版本、终止模式和时长；**评价缓存**另绑定目标集合、观察器/几何、源规则、权重、代价定义和指标版本。若核心早停影响物理运行，其监听目标集合也必须进入物理缓存键。

结果至少区分：`passed`、`failed`、`invalid`、`unknown`。有效核心失败可供零引燃约束否决，但不等于获得完整损失；无效请求和资源限制不能计作火灾失败，也不能计作成功。所有汇总分母对应预先声明的情景，不随缺失运行静默缩小。

建议的未来实验目录（当前不创建）：

```text
runs/research/<study-id>/
  protocol.json                 冻结配置、来源、目标与源政策
  inventory.json                基准身份、资格、住户信息及未知项
  actions.json                  行动目录、真实几何和面积口径
  evaluation-cache/             逐情景结果、模式与完整性
  search-trace.jsonl            请求、候选变化、拒绝/未知原因
  selection.json                打开留出前冻结的候选
  confirmation/                 留出、完整时长、尺度与机制验证
  plans.geojson                 行动、核心与保留建筑图层
  report.md                     核心结果、干预代价、适用范围
```

普通住户身份只用于受影响去重和研究控制；对外成果使用汇总或去标识数据。工程实现不需为首个闭环增加专门网页编辑器，先复用现有空间导出和回放能力。

| 新流程中的 `outer_proxy/inner_proxy` 分配、条带纯效果模式、多形状族调度 | 从建筑拆除主线中排除这些分支，保持新入口集中 | `joint.py/joint_diverse.py/adaptive.py` 原实现留给旧研究；没有全仓依赖和复现审计前不整文件删除 |

| `prefetch_batuan_*`、`complete_batuan_*`、`continue_batuan_observed_study.py` 等操作脚本 | 新研究以统一入口的准备/搜索/确认/恢复阶段替代，不再增加同类专用脚本 | 历史运行依赖、文档命令及恢复责任都迁移并验收后，才考虑归档或删除具体脚本 |
| 旧静态可见性/传播率规划、组件辐射、飞火、材质编辑与已有测试 | 与当前主线隔离，暂缓新增功能 | 暂无删除依据；它们承担其他模拟器或验证任务，不因新论文不用而删除 |

已发现真实的脚本间依赖：`run_batuan_multiscenario_search.py` 导入 adaptive/protection 驱动，`run_batuan_joint_search.py` 导入 protection 驱动，`run_batuan_observed_joint.py` 导入 joint 驱动；审计、渲染与测试也使用这些入口。因此不把 `scripts/` 当作全部可丢弃的临时代码。

删除前采用同一标准：检索所有引用与文档命令 → 保存原输入/输出和来源 → 迁移调用者 → 检查恢复与关键结果等价 → 删除重复实现。曾被实验指纹引用的版本仍需可恢复。现有工作区未提交的飞火、观测与桥梁审计等改动保持原样。
