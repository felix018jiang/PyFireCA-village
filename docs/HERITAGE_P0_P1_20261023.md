## 2. 缺失资料及其用途

| 待补资料 | 需要确定什么 | 当前处理 |
|---|---|---|
| 遗产附属范围与细部 | 鼓楼、桥梁的檐口及附属构件是否完整，活动空间如何划定 | 本体 ID 已确认；尚不把屋面轮廓当作全部文化空间 |
| 更新物理案例几何 | 同步 B0024 的最新位置并核对全部传热连接 | 已记录差异并阻止旧物理案例被误用为最新输入 |
| 普通建筑可调整资格 | 是否允许整栋拆除、部分退让，是否具有其他保留价值 | 真实候选为空；合成候选明确标为技术假设 |
| 固定普通建筑源 | 建筑 ID、局部初起火或整栋同时燃烧、点火位置 | 不自动把桥附近房屋选为真实源 |
| 独立建筑语义与檐口 | 嵌套/重叠轮廓、相连结构、檐口和连廊 | 涉及重叠的拆除请求被拒绝；目标共享温度格不能判为通过 |
| 住户与使用情况 | 受影响住户身份、建筑用途、搬迁影响 | 住户数为 `null`，不记为零 |
| 楼层与建筑面积 | 面积口径及使用空间损失 | 当前仅报告轮廓投影面积 |
| 鼓楼活动场地、桥头空间和通路 | 集会、通行与必要公共空间边界 | 未宣称施工及文化空间条件已满足 |
| 拆后地表及残余木构件 | 是否清除木构件、露出地面是否可燃 | P1 仅支持明确声明的“清除残余后不燃地表”假设 |
| 木材、含水率及场地物理校准 | 真实建筑引燃与传播参数 | 沿用可追溯的合成等效燃料，尚未完成实测校准 |

这些缺口已进入机器可读审计结果，不需要通过伪造身份、零住户或默认合法候选来启动技术验证。

复用原 V3 求解器，没有改变温度演化和引燃规则。原植被清理接口及历史研究入口继续可用。

拆除按建筑几何实施，不能仅根据原单格主归属擦掉整格。对发生变化的共享格，只有保留建筑与原格的等效材料参数一致且有可核对参考时，才按剩余真实屋面面积更新全部广延量；异质或无参考情况拒绝执行。未占用部分按声明的不燃地面处理，仍不具备亚格独立温度或真实实体墙能力。

每个核心对象分别记录首次引燃；任一核心引燃构成联合失败。普通建筑源在零时刻点燃不触发核心早停。成功要求完整运行至指定时长；共享目标温度格、边界引燃等会导致 `invalid`。早停失败不能用于完整灾损比较。状态、终止方式、目标清单和观察器均进入结果指纹。

## 4. 已保存的物理模拟

两组均使用 2 m 网格、1200 s 时长、显式合成木建筑参数，源为普通建筑 S，核心为合成鼓楼 G 和合成风雨桥 F。每组只评价预先指定的两个方案，没有搜索、枚举或最优性判断。

| 合成控制 | 手工方案 | G 首次引燃 | F 首次引燃 | 核心结果 |
|---|---|---:|---:|---|
| 短耦合范围连接控制：辐射半径 3 m、阈值 520 K | 无拆除 | 786.00 s | 916.36 s | 失败 |
| 同上 | 拆除中间建筑 M，4 m² | 至 1200 s 未引燃 | 至 1200 s 未引燃 | 通过 |
| 跨空隙压力控制：半径 8 m、阈值 350 K | 无拆除 | 178.00 s | 198.00 s | 失败 |
| 同上 | 拆除中间建筑 M，4 m² | 211.00 s | 247.00 s | 失败 |

第一组验证建筑干预能够改变传播和保护结果；第二组验证拆后空地不会被代码视作自动阻火墙。半径和阈值属于显式控制设置，350 K 是易引燃压力假设；两组不用于推导真实木材安全间距，也不能把组间差异归因于单一参数。

普通建筑配对比较使用同一保留集合 S、U；不会把被主动拆除的 M 从分母中移走后，计作火灾损失改善。受影响住户未知，拆除投影面积单独记账。

结果分别保存于：

- `runs/research/heritage-p1-synthetic-20261023-r3`
- `runs/research/heritage-p1-cross-gap-20261023-r3`

每组包含生成输入、冻结协议、两份原生物理案例、`final-state.npz`、逐核心评价及局部米制方案 JSON。投影场地输出转换为 WGS84 GeoJSON；局部合成坐标以 `.local-metric.json` 明确标记。已从四份保存末态直接核对核心引燃时间、源点零时刻引燃、完整时长和无燃料格未引燃，并验证案例重新加载后的物理指纹；没有为该核对新增 CA 求解。能量误差均通过既有 `check_final` 的绝对＋相对容差，汇总保留原始误差与容差。此前 r1/r2 输出保留为阶段记录，以 r3 及其指纹为当前证据。

## 5. 复现入口

从仓库根目录执行；输出目录必须为新的路径，避免覆盖已保存证据。

```bash
.venv/bin/python scripts/run_heritage_study.py \
  --config examples/research/heritage/batuan-p0.json \
  --audit-only --output runs/research/batuan-heritage-p0-recheck

.venv/bin/python examples/research/heritage/synthetic_case.py \
  --output runs/research/heritage-p1-recheck/inputs
.venv/bin/python scripts/run_heritage_study.py \
  --config runs/research/heritage-p1-recheck/inputs/study.json \
  --output runs/research/heritage-p1-recheck/results

.venv/bin/python examples/research/heritage/synthetic_case.py \
  --radius-m 8 --ignition-temperature-k 350 \
  --output runs/research/heritage-p1-gap-recheck/inputs
.venv/bin/python scripts/run_heritage_study.py \
  --config runs/research/heritage-p1-gap-recheck/inputs/study.json \
  --output runs/research/heritage-p1-gap-recheck/results
```

真实数据审计依赖本机已有岜团村案例。合成案例只依赖仓库中的燃料参数文件及已声明的村落/几何依赖。源和方案由 JSON 显式指定，入口没有复杂优化。
