# 侗族传统村落防火分隔：60分钟延时与同面积位置对照

日期：2026-11-03。研究定位按用户最新要求固定为：**元胞自动机模拟侗族传统村落火灾传播过程和形态，通过算法确定最佳防火线位置，并评价其防护效果。** 本轮是既有方案的应用验证，不增加算法创新目标，也不继续未闭合的组合最优性搜索。

## 研究问题与首批范围

1. 岜团三栋与平岩五栋方案在观察期由20分钟延至60分钟后是否仍保护指定核心？
2. 在拆除栋数相同、名义面积非常接近且面对完全相同火源时，位置替换怎样改变核心引燃时间及传播形态？
3. 各方案在20、40、60分钟的累计引燃范围、普通建筑受火和最终仍在燃烧的状态有什么差别？

两村分别使用2个冻结历史源、3个方案、1 m/0.5 m两种局部屋面尺度，共24份完整3600 s模拟。检查点从同一条完整模拟的节点首次引燃和燃尽时间提取，不重复运行三个时长，也不把它们当作独立火灾。所有失败方案继续运行至观察终点。

## 物理输入与公平比较

保留现有材料、能量、含水率、地形、接触和面积积分辐射。无风、无飞火、15 m辐射范围保持。背景保留完整父案例，局部屋面采用1 m/0.5 m，辐射面积求积0.5 m。核心身份与共享燃料规则不变。

每个火源的共同细化集合为：三臂干预建筑并集、所有核心、固定源。三臂采用相同布局和精确点火面；不生成本批不会使用的后备源细化。新共同细化范围与历史批次不同，因此本轮自身1200 s检查点才是延时比较的基准，不能把旧温度轨迹直接拼为新模拟前缀。此处没有改变热传播方程或调低点燃门槛。

累计点燃面积按物理节点覆盖面积计量，不重复计算共享归属。建筑数量按有效建筑身份另列，标注身份歧义保留。普通建筑比较除各臂原始结果外，增加所有方案共同保留对象集合的比较，避免因主动拆除减少统计分母。

## 实现、预算和验收

准备入口：[冻结输入与火源](../scripts/prepare_heritage_followup_20261103.py)。执行入口：[固定多臂比较](../scripts/run_heritage_fixed_comparison.py)。配置保存于 `examples/research/heritage/followup-20261103/`；两村输出分别为 `runs/research/heritage-followup-batuan-20261103`、`runs/research/heritage-followup-pingyan-20261103`。

先执行几何容量预检并冻结源码、配置、源指纹和库存，再从冻结副本运行。每村最多12个不同方案/情景评价，累计墙钟软预算14400 s，单个已开始求解可超过剩余软预算；低于5 GB可用磁盘停止。中断和未计算项记为未知，缓存须完成文件完整性校验后才能复用。预算不通过重启重置。

完成要求：

- 24/24份有效、达到3600 s；逐项验证源ID、点火面、源能量、父案例和共同布局。
- 保存逐核心首次引燃、20/40/60分钟结局、累计点燃面积、节点与建筑传播范围、终点活动燃烧情况。
- 逐方案核对名义、实际清空和共享保留面积，双尺度按任一尺度引燃合并核心结局。
- 核心发生引燃仅表示模型中的局部组件引燃，不直接解释为整栋完全烧毁。
- 执行小规模自动化测试及代表性原生存档恢复；归档结果、CSV、传播图和本轮报告。

60分钟未引燃只能支持本批条件下的保护结果；终点仍有燃烧时保留其状态。此批不证明新时长下全村最优，也不把历史20分钟最优性证书延伸到60分钟。后续位置优化由本轮实际结果决定。
